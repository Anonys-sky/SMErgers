---
name: Role workspace design
description: User-requested role separation and visual direction for SMErgers.
---

The user wants separate pages for the project director, client, finance and other
operational roles, not one generic page with the same tasks for everyone.

**Why:** They asked to make it clear what the system does and how each person
completes their functions.

**How to apply:** Keep task guidance and available controls specific to each role.
Preserve the distinction between project-manager review, director sign-off,
client confirmation and finance billing.

The user supplied Employa employee-document and Red Carpet profile/checklist
screens as the reference direction and asked to apply that format to all UI/UX.

**Why:** The user asked for these references, rather than the earlier long-form
landing-page presentation.

**How to apply:** Maintain a coherent workspace shell with persistent navigation,
profile/project summaries, tabs, compact work tables and contextual checklists
and history. Adapt the references to event-change management, not HR content.

The blue workspace UI (sidebar shell, accent #3569c8) is the one the user wants;
they rejected the green/parchment "field notes" look as the old version (2026-10-23).
Client access follows the WhatsApp-link model from the GitHub work: any job's client
link opens for the Client role and selects that event for the client workspace.

**Why:** A hard lock to one selected sample client broke the guided live-demo hand-over.

**How to apply:** Keep new UI work in the blue workspace system; never reintroduce the
green theme. Keep the client page reachable by link; keep team pages and the API blocked for clients.
